Scroll drives the scene

Four keyframes, one eased scroll position. Every parameter between them is interpolated — camera angles, displacement, colours — while the mesh type and lighting rig step at the midpoint, because there is no halfway between a sphere and a plane.

Keep scrolling.

One owner per property

The rig owns every parameter it names, for the whole page. Nothing else writes them, so there is no second animator to fight and no state to reconcile — the classic failure mode when a scroll library and a UI both reach for the same camera.

Draw only what is needed

The renderer marks itself dirty when a parameter changes and skips the draw when nothing did. It also measures its own frame time and trades resolution for frame rate when the GPU falls behind, taking the pixels back when the budget allows.

Then clean up after yourself

Listeners are registered against one AbortController and the renderer releases its buffers, vertex arrays and program on pagehide. Setup and teardown are symmetric.
